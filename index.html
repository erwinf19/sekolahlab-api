Perilaku API.

AreaRancangan
Baca dataSemua GET data sekolah bersifat publik. Semua nama, akun, dan profil adalah data fiktif.
LoginAkun demo tetap; token bertanda tangan berlaku 3.600 detik. GET /auth/me membutuhkan token.
RegisterValidasi dan respons 201 saja. Akun tidak disimpan, tidak dapat digunakan login, tidak mengembalikan token.
Edit / hapusHanya admin. PATCH dan DELETE mengembalikan meta.simulation=true dan meta.persisted=false. GET berikutnya tidak berubah.

PenyimpananFixture JSON ikut deployment. Ubah fixture lalu deploy ulang untuk memperbarui data dasarnya.

KONTRAK V1

Alur login dan akun demo.

Tersedia 10 akun fiktif dengan tiga role: admin, teacher, dan student. Buka daftar akun di beranda untuk melihat email dan password. Admin dapat mencoba edit/hapus; guru dan siswa dapat mengakses profil dan membaca data.

  1. Kirim email dan password ke POST /api/v1/auth/login.
  2. Ambil data.access_token dari respons.
  3. Kirim header berikut ke endpoint yang membutuhkan token.
  4. Jika mendapat 401 karena token kedaluwarsa, login kembali. Refresh token belum masuk v1.
Authorization: Bearer <access_token>
Content-Type: application/json

Setup lokal: jalankan npm ci, npm run setup, lalu npm run dev. Setup membuat .env dengan secret acak tanpa menimpa file yang sudah ada. Pada Netlify, atur JWT_SECRET minimal 32 karakter di environment variable Functions. Jika secret tidak ada atau terlalu pendek, login dan verifikasi token mengembalikan 503.

Register: name 2–100 karakter, email valid maksimal 254 karakter, password akun baru 8–72 karakter, dan password_confirmation harus sama. Email dinormalisasi menjadi lowercase dan dipangkas spasinya. Password tidak dipangkas. Nama dipangkas sebelum validasi. Email fixture yang sudah dipakai menghasilkan 409. Email baru yang sama bisa diregister ulang karena tidak disimpan.

Login: email valid dan password wajib terisi, maksimal 72 karakter. Kredensial salah selalu 401 dengan pesan umum. Field body yang tidak dikenali ditolak dengan 422. Role atau password hash tidak bisa diatur melalui register.

POST/api/v1/auth/loginLogin dengan akun demoPublik

Utama Auth

Cocokkan email dan password dengan akun demo. Token ditandatangani backend; secret disimpan sebagai environment variable. Masa berlaku: 1 jam. Password tidak pernah dikembalikan. Jika JWT_SECRET belum dikonfigurasi, endpoint mengembalikan 503.

Request body

{
  "email": "admin@sekolahlab.com",
  "password": "<password-akun-demo>"
}

Respons 200

{
  "success": true,
  "message": "Login berhasil.",
  "data": {
    "user": {
      "id": 1,
      "name": "Admin SekolahLab",
      "email": "admin@sekolahlab.com",
      "role": "admin",
      "photo_url": "https://api.dicebear.com/10.x/avataaars/svg?seed=sekolahlab-admin-001"
    },
    "access_token": "<token-demo-dari-backend>",
    "token_type": "Bearer",
    "expires_in": 3600
  }
}

Error yang mungkin: 400, 401, 422, 500, 503, 413, 415. Lihat tabel status dan aturan validasi.

Utama Auth

KONTRAK V1

Query pencarian dan pagination.

orderasc atau desc. Default asc, kecuali berita desc.order=asc

GET /api/v1/students?search=alya&class_id=1&page=1&limit=10
GET /api/v1/teachers?subject_id=1&sort=name&order=asc
GET /api/v1/news?category=kegiatan&sort=published_at&order=desc

Filter digabung dengan AND → sorting → pagination. Nilai sort yang sama diurutkan lagi berdasarkan ID naik agar stabil. meta.total adalah jumlah setelah filter, sebelum pagination. Halaman melebihi hasil mengembalikan 200 dengan data: []. Tanpa hasil, total: 0 dan total_pages: 0.

Parameter tidak dikenal, parameter berulang, integer tidak valid, enum tidak sesuai, atau field sort tidak diizinkan menghasilkan 400. Filter ID yang formatnya valid tetapi tidak ada menghasilkan daftar kosong. Detail menggunakan ID positif; ID valid yang tidak ada menghasilkan 404. Pada GET detail, query selain yang didokumentasikan ditolak.

KONTRAK V1

Aturan edit dan hapus.

PATCH memakai perubahan sebagian. Minimal satu field; body kosong, field asing, field hanya-baca, atau nilai null yang tidak diizinkan menghasilkan 422. Autentikasi diperiksa sebelum data resource. DELETE tidak membutuhkan body.

ResourceField yang boleh dieditHanya baca
Siswanis, name, gender, birth_date, class_idid, user_id, photo_url
Guruteacher_code, name, gender, subject_idsid, user_id, photo_url
Pelajarancode, name, descriptionid
Beritatitle, excerpt, content, image_url, categoryid, slug, author_id, published_at

Nama/judul: 2–150 karakter. NIS/kode: 1–30 karakter, unik dengan perbandingan case-sensitive di fixture (kecuali record sendiri); duplikat menghasilkan 409. Deskripsi/ringkasan: 1–500 karakter. Isi berita: 1–10.000 karakter. URL berita: HTTPS valid, maksimal 2.048 karakter, tanpa username/password pada URL. Tanggal lahir harus tanggal kalender valid dan tidak di masa depan. class_id dan semua subject_ids wajib merujuk fixture yang ada; kesalahan relasi menghasilkan 422. Array subject_ids harus berisi integer positif unik dan minimal satu item.

Semua field string dipangkas spasinya sebelum validasi kecuali password. Edit tidak mengubah fixture akun users yang terhubung. Setiap PATCH selalu memakai data awal sebagai dasar, bukan hasil PATCH sebelumnya. Slug berita tetap sama meski judul dalam respons simulasi berubah.

Penghapusan relasi tidak disimulasikan secara berantai. Tidak ada endpoint tambah siswa/guru/pelajaran/berita di versi pertama; endpoint POST hanya untuk auth.

KONTRAK V1

Format respons dan error.

Respons API menggunakan Content-Type: application/json. GET detail dan auth mengembalikan objek pada data; daftar mengembalikan array beserta meta pagination. Respons endpoint utama selalu JSON. Preflight OPTIONS untuk CORS mengembalikan 204 tanpa body.

{
  "success": false,
  "message": "Validasi gagal.",
  "errors": {
    "name": [
      "Nama minimal 2 karakter."
    ],
    "class_id": [
      "Kelas tidak ditemukan."
    ]
  }
}
StatusMakna
200GET, login, PATCH simulasi, atau DELETE simulasi berhasil.
201Register simulasi berhasil; bukan bukti akun tersimpan.
400JSON tidak bisa dibaca, ID path tidak valid, atau query tidak valid.
401Kredensial salah atau token hilang/tidak valid/kedaluwarsa.
403Token valid tetapi role bukan admin pada PATCH/DELETE.
404ID tidak ditemukan atau path API tidak tersedia.
405Path dikenal tetapi HTTP method tidak didukung; sertakan header Allow.
409Email register atau NIS/kode edit berbenturan dengan fixture.
415Request yang memerlukan JSON menggunakan Content-Type selain application/json.
422JSON valid tetapi bentuk/field/nilainya tidak sesuai aturan.
413Body melebihi batas 100 KB.
503JWT_SECRET belum ada atau kurang dari 32 karakter; endpoint publik tetap bisa diakses.
500Kesalahan server; tidak menampilkan stack trace atau secret.

Semua error menggunakan { success: false, message, errors }. errors berisi objek per field untuk validasi/query; gunakan {} bila tidak terkait field. Body JSON harus berupa objek, bukan array atau nilai primitif. Body dibatasi 100 KB. Nilai ID path/query harus angka desimal positif tanpa nol di depan. Query tidak diterima pada auth, health, detail, PATCH, atau DELETE. HEAD tidak didukung (405); OPTIONS ditangani untuk CORS. Kode 405 berlaku umum; 415 berlaku pada POST/PATCH. OPTIONS untuk CORS ditangani otomatis.

KONTRAK V1

Contoh untuk frontend.

Untuk mencoba lokal, gunakan base URL http://localhost:3000/api/v1. Untuk Netlify, ganti dengan domain deployment milikmu.

1. Ambil daftar siswa

const BASE_URL = 'http://localhost:3000/api/v1';

const response = await fetch(`${BASE_URL}/students?page=1&limit=10`);
const result = await response.json();
if (!response.ok) throw new Error(result.message);
console.log(result.data); // Array siswa
console.log(result.meta); // Informasi pagination

2. Login dan ambil profil

const loginResponse = await fetch(`${BASE_URL}/auth/login`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    email: 'admin@sekolahlab.com',
    password: '<password-akun-demo>'
  })
});
const login = await loginResponse.json();
if (!loginResponse.ok) throw new Error(login.message);
const token = login.data.access_token;

const profileResponse = await fetch(`${BASE_URL}/auth/me`, {
  headers: { Authorization: `Bearer ${token}` }
});
const profile = await profileResponse.json();
if (!profileResponse.ok) throw new Error(profile.message);
console.log(profile.data);

3. Simulasi edit siswa

const editResponse = await fetch(`${BASE_URL}/students/1`, {
  method: 'PATCH',
  headers: {
    'Content-Type': 'application/json',
    Authorization: `Bearer ${token}`
  },
  body: JSON.stringify({ name: 'Alya Putri Utami' })
});
const edited = await editResponse.json();
if (!editResponse.ok) throw new Error(edited.message);
console.log(edited.data); // Hasil simulasi
// GET /students/1 berikutnya tetap mengembalikan data awal.
